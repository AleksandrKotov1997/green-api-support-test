# GREEN-API: проверка методов WhatsApp API

Тестовое задание на должность специалиста технической поддержки 2 линии.

[Открыть страницу](https://green-api-support-test.vercel.app/) · [Репозиторий](https://github.com/AleksandrKotov1997/green-api-support-test)

Страница вызывает четыре метода GREEN-API: `getSettings`, `getStateInstance`, `sendMessage` и `sendFileByUrl`. Параметры подключения и кнопки расположены слева, ответ API — справа в поле только для чтения, как в макете задания.

## Запуск

Приложение написано на HTML, CSS и JavaScript. Устанавливать зависимости и собирать проект не требуется. Для локального запуска нужен любой статический HTTP-сервер, например Python 3:

```sh
python3 -m http.server 8080 --bind 127.0.0.1
```

Откройте http://localhost:8080 в браузере. HTTP-сервер нужен для загрузки JavaScript-модулей; открытие `index.html` через `file://` не подходит.

## Использование

1. Создайте WhatsApp-инстанс на бесплатном тарифе Developer в [личном кабинете GREEN-API](https://console.green-api.com/).
2. Подключите WhatsApp, отсканировав QR-код через раздел связанных устройств на телефоне.
3. Введите `idInstance` и `ApiTokenInstance` из личного кабинета.
4. Нажмите `getSettings` или `getStateInstance`. В поле «Ответ» появится тело ответа API в формате JSON.
5. Для `sendMessage` укажите номер с кодом страны и текст сообщения. Пробелы, скобки, дефисы и начальный `+` в номере допускаются; приложение преобразует номер в `chatId` вида `77771234567@c.us`.
6. Для `sendFileByUrl` укажите номер получателя и прямую общедоступную HTTP(S)-ссылку на файл. Название `fileName` определяется из последней части пути ссылки, поэтому она должна содержать имя с расширением, например `https://example.com/image.png`. Ссылки на страницы предпросмотра облачных хранилищ не подходят.

На узких экранах поле ответа размещается под формами. Успешный ответ отправки содержит `idMessage` и означает принятие запроса API, а не подтверждение доставки. Доставку следует проверять в WhatsApp. Бесплатный тариф ограничивает число чатов; используйте один согласованный тестовый контакт.

## Обработка ошибок

Пустые параметры, некорректные номера и ссылки проверяются до запроса. Ошибка подсвечивает соответствующее поле. Ответы HTTP с ошибкой отображаются без подмены тела; код HTTP указан под полем ответа. Сетевые ошибки и превышение времени ожидания отображаются отдельно. Во время запроса кнопки блокируются. Автоматических повторов отправки нет: при сетевой ошибке запрос мог быть принят, поэтому перед повтором следует проверить чат.

## Параметры подключения

Для запросов используется официальный универсальный хост `https://api.green-api.com`. Токен вводится в поле пароля, не записывается в localStorage, cookies, исходники или журналы приложения. Запросы идут из браузера непосредственно в GREEN-API. На странице нет сторонних скриптов, шрифтов и аналитики.

## Структура

```text
index.html             Разметка страницы
styles.css             Стили и адаптация макета

tests/                 Проверки валидации и HTTP-клиента

```

## Проверки

Для автоматических проверок нужен Node.js 22 или новее. Внешних зависимостей нет:

```sh
npm test
```

Проверки используют подмену сетевого ответа только внутри тестов и не отправляют реальные сообщения. Приложение всегда работает с настоящим API.

Дополнительно все четыре метода проверены с авторизованным WhatsApp-инстансом. Получение тестового текста и картинки подтверждено получателем. Подробности — в [отчёте о проверке](./docs/verification.md).

## Публикация на Vercel

Репозиторий `AleksandrKotov1997/green-api-support-test` подключён к отдельному проекту Vercel `green-api-support-test`. Production-ветка — `main`: изменения, отправленные в неё на GitHub, автоматически публикуются по адресу страницы.

Используется пресет `Other` и корневая папка проекта. Файл `vercel.json` отключает установку зависимостей и сборку: Vercel публикует готовые HTML, CSS и JavaScript. Файл `.vercelignore` исключает из публикации тесты, отчёт и локальные служебные файлы. Переменные окружения для приложения не нужны: параметры подключения пользователь вводит на странице.

При подключении другого репозитория добавьте его в список разрешённых для приложения Vercel в настройках GitHub, а затем выберите в `Vercel → Project Settings → Git`. Для публикации используйте отправку готовых изменений в production-ветку.
